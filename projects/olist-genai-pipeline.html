E-commerce analytics pipeline with a GenAI insights assistant

We took the Olist Brazilian e-commerce dataset from raw CSVs to a published dashboard: schema design, cleaning, loading, SQL analysis and Tableau. Then we added a retrieval-augmented generation (RAG) assistant, so anyone can ask a business question in plain English and get an answer grounded in the data, without writing SQL.

Business questions

  1. Which product categories drive the most revenue?
  2. Does delivery time affect customer review scores?
  3. What is the repeat purchase rate?
  4. How does seller performance vary across revenue and ratings?

The pipeline

  • Schema: a normalized PostgreSQL schema of 9 tables with primary keys, foreign keys and constraints.
  • Cleaning and loading: a Python notebook (pandas, SQLAlchemy) that cleans, validates and loads ~120K real orders.
  • Analysis: SQL with multi-table joins, aggregations and subqueries to answer each business question.
  • Dashboard: query results exported to an interactive Tableau Public dashboard.

Data quality process

  • Verified referential integrity across every foreign key before loading: zero orphaned records.
  • Found and resolved 2 product categories with no English translation in the source data.
The real data corrected two of our schema assumptions.

customer_unique_id is not unique: one customer can place several orders under the same identity. And review_id is not a standalone primary key, because Olist reuses review IDs across grouped orders, so the reviews table needed a composite key.

Key findings

  • Health & beauty and watches & gifts are the top-revenue categories.
  • Delivery time has a clear relationship with review scores: orders with longer delivery windows get lower ratings.
  • The repeat purchase rate is low, about 3%, which is typical of marketplace buying behavior.
  • Seller revenue and review quality vary independently. Some high-revenue sellers have below-average ratings, which shows where customer satisfaction needs attention.

The GenAI insights assistant

The assistant sits on top of the SQL layer and works in four steps:

  1. Key business metrics are precomputed in SQL and turned into plain-English summary chunks.
  2. Those summaries are embedded locally with sentence-transformers (all-MiniLM-L6-v2) and stored in a Chroma vector database.
  3. A user's question is embedded and matched against the most semantically similar summaries.
  4. The retrieved summaries go to the Claude API as context. Claude writes an answer grounded in them, or says plainly that the data doesn't support an answer instead of guessing.

The Streamlit app puts the Tableau dashboard and the chat interface side by side.

Validation

We tested the assistant against a hand-curated set of business questions, some answerable from the data and some deliberately out of scope.

Fixing a retrieval recall gap

Retrieving only the top 2 most similar chunks missed some in-scope answers. Raising retrieval to the top 3 fixed it. The assistant now answers in-scope questions correctly and declines out-of-scope ones instead of hallucinating.

What's in the repo

Analytics pipeline

  • schema.sql: the full PostgreSQL schema (9 tables, keys and constraints)
  • business_questions.sql: the queries behind the four business questions
  • Ecommerce_pipeline.ipynb: cleaning, validation and loading
  • tableau exports/: CSV exports used to build the dashboard

GenAI / RAG layer

  • s1_generate_summaries.py: inspects the database schema and tables
  • s1b_generate_summaries.py: generates the business summary chunks from PostgreSQL
  • summaries.json: the precomputed summaries
  • app.py: the combined Streamlit app (dashboard + RAG chat)
