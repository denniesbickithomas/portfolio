One view of every project and every person

The marketing agency Off Madison Ave ran its work in Basecamp 4 but couldn't see overall project status or team workload in one place. Our five-person team turned that frustration into a scoped problem, built a secure data pipeline, and handed the client a dashboard they fully own.

Client
Off Madison Ave (marketing / PR agency)
When
Fall 2025 · final presentation Nov 25, 2025
Focus
Client discovery · API integration · dashboard design
Stack
Basecamp 4 API · OAuth 2.0 · Apps Script · Google Sheets · Looker Studio
Problem Approach The dashboard Results Limits & next steps

The problem

Basecamp is good for running individual projects, but it has no unified view of status across projects and no view of how work is spread across people. Managers clicked through separate project and person pages by hand. The result was duplicated work, patchy communication across platforms, and status tracking done manually.

The hardest part was scoping, not coding.

The original request was close to "fix our workflow." A large share of the project went into discovery with the agency's teams. From that we narrowed the request to one problem we could solve in a semester: real-time visibility into project status and team bandwidth.

Approach

1. Security first, explained to a non-technical client

We registered an OAuth 2.0 app with Basecamp (37signals Launchpad). On Sep 25, 2025 we ran an API explainer session for the client covering read-only access, scoped and expiring tokens, and HTTPS, so they understood what the integration could and couldn't touch before we built it.

2. Extract and flatten the data (Google Apps Script)

  • Token handling: tokens refresh automatically, and credentials are stored in Apps Script's PropertiesService rather than in the code.
  • Mapping the API: a config object follows Basecamp's hierarchy of projects → to-do sets → to-do lists → to-dos.
  • Import: a routine loops through every project, follows paginated endpoints, flattens the nested JSON, and writes clean rows to Google Sheets.
  • Built for non-technical users: a custom Sheets menu lets staff refresh the data or check token status with one click.

The dashboard

A two-page Looker Studio report, refreshed weekly on a schedule, with a manual refresh option:

  • Project Status view: global filters for project and date range; scorecards for total, completed, pending and overdue tasks; a task-progress chart; a task table; and a workload tree map by assignee.
  • People view: each person's share of the workload, their project and task counts, and per-person task tables.

Results

  • Delivered a working dashboard that the client owns: the script, the Sheet and the report. It brings together information that previously meant jumping between many Basecamp views.
  • Replaced manual status gathering. Managers can now see workload imbalance and overdue work in one place, and we recommended using it in weekly or bi-weekly resourcing meetings.
  • The structured Sheet output means the agency can feed Basecamp data into other workflows and AI tools later.

Limits & next steps

  • The People view works best for small and mid-sized teams.
  • The dashboard can only show what Basecamp's API exposes. Client information, for example, wasn't available.
  • Possible next steps are adding Box or Excel sources, or moving to a native PM tool if headcount grows a lot.
